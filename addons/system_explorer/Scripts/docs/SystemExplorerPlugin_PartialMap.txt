Diagnostics/SystemExplorerDebugLogger.cs
- Defines the internal sealed general debug-log sink under SystemExplorer.Diagnostics.
- Receives a dynamic Func<bool> enablement provider, exposes its current read-only IsEnabled state, and evaluates it for every Log(...) and LogOperation(...) call.
- Provides lazy message/detail factory overloads so expensive diagnostics are not constructed while debug output is disabled.
- Owns the [SystemExplorer] persistent-file entry prefix and the existing operation/details formatting, including the whitespace check and -> separator.
- While dynamic DebugState is enabled, Log(...) and LogOperation(...) append each complete entry only to a process-stable file under user://system_explorer/logs; they do not route ordinary diagnostics, file-open status, write-failure status, or dispose-failure status through GD.Print or any console fallback. The filename is derived from the Godot process start time plus process id, so a new managed logger after assembly reload reopens the same process log while a full Godot restart produces a new file. File rows add millisecond timestamp and managed thread id, normalize embedded newlines to one physical row, flush synchronously per entry, use the repack's explicit System.Environment and System.IO.FileStream/System.IO.FileMode/System.IO.FileAccess/System.IO.FileShare forms where relevant to avoid Godot/C# name conflicts, and defensively disable only the file sink if directory/open/write/flush/dispose fails so diagnostic file I/O cannot break plugin operations or recurse through the logger; if that sink fails, diagnostics fail closed and remain silent.
- Provides one deliberately narrow main-thread LogPersistentFileOnlyOperation(...) path for timing-sensitive crash-tail editor-boundary breadcrumbs. It checks dynamic DebugState before use, writes through the same process-stable file/lock/single-line/timestamp/thread-id path, flushes synchronously, and fails closed. This main-thread API remains separate because it is the particularly defensive crash-tail path and does not create or cache a cross-generation sink. CreatePersistentFileOnlyDiagnosticSink() likewise remains a distinct worker/unload-safe path: it captures neither SystemExplorerPlugin nor the dynamic DebugState provider, performs no GD.Print/ProjectSettings/Godot access when the returned delegate executes, and fails closed if the persistent file sink is unavailable or disposed.
