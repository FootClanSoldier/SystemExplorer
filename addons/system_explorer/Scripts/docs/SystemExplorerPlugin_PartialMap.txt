- Declares the folder-bindings resource path, shared folder-binding dialog field, shared Shortcut Conflict dialog field, and normal/bound folder colors, and coordinates dock creation, atomic persistent-state initialization, startup-only folder synchronization, reload-safe editor integrations, and idempotent teardown in the core plugin order.

- Owns one lazy plugin-instance SystemExplorerDebugLogger and supplies it with the dynamic () => DebugState provider, so the current Project Settings value is read when each log method runs rather than cached during logger construction.
- Keeps locator construction behind a lazy holder so lazy Refactor Namespace preflight composition always receives a fully constructed non-null locator.
- Keeps autosave composition behind one lazy holder that constructs exactly one autosave service, passes that same instance to the batch service, and passes those same autosave and batch instances to the coordinator.

Partials/SystemExplorerPlugin.RenameRemove.cs
- Handles rename and remove operations for systems, folders, scripts, linked scenes, and direct scene entries.
- Provides the shared selected-item Rename dialog opener used by keyboard routing, validates the exact selected metadata, and captures script rename tree state before dialog focus; context-menu opening preserves its existing pre-popup capture and both paths use the same defensive bool-returning dialog opener.
- Handles file deletion, file/folder renames, forced expansion after renames, and updating script/scene entries after path changes.
- Removes a non-deleted script by exact captured system/entry occurrence rather than a global first entry match; if the physical file is deleted, removes every virtual script or scene reference whose normalized path points to a deleted file.
- Calls mutate-only folder-binding migration/removal helpers after successful system/folder mutations and reports whether bindings changed.
- Uses reversible coordinated persistence for metadata-only system/folder rename and virtual remove, leaving rename/remove UI completion and tree rebuild until the coordinated commit succeeds.
- Uses a separate irreversible systems-first persistence policy after physical delete: repaired systems metadata is saved before binding cleanup, and neither files nor in-memory metadata are rolled back after physical deletion.
- Delegates technical open-buffer autosave orchestration to ScriptEditorBufferAutosaveCoordinator and translates technical autosave failures through ScriptFileOperationAutosaveFailureMessageBuilder while retaining warning, debug logging, abort, restore, rollback, sync-suppression, tab-closing, filesystem, metadata, and editor-state decisions in the plugin.
- Physical remove first collects and validates every resource target without editor or metadata mutation, captures a deep systems/bindings baseline, then runs Persistence.cs's strict metadata preflight before any Script Editor autosave/tab close, resource deletion, or UID deletion. folder_bindings.json is included only for full system/folder removal when an actual binding definition may be removed.
- After metadata preflight, physical remove's editor preparation rejects multiple matching Script resources, uses single-buffer autosave, closes through ScriptEditorTabService.TryCloseScriptTab(...), requires the entire case-insensitive path to be released, and suppresses ScriptEditorSync during editor preparation.
- After preflight, physical remove is best-effort across every prepared resource in stable batch order. It retains separate raw Godot and System.IO existence observations, requires both views to verify presence before each mutation, records the delete call outcome independently, and postpones terminal result classification until an end-of-batch reconciliation has re-read disk status.
- After an actual delete attempt, verified System.IO status for the globalized path is authoritative: verified global disk absence is classified as deletion even when RemoveAbsolute(...) returned an error or Godot's first/final observation still reported the file present. Such recovered call or observation anomalies are debug-only and do not make an otherwise complete remove operation user-visible as incomplete.
- Reconciles UID sidecars only after their resource files have been terminally classified as verified deleted. UID files already missing before their own delete phase are normal; attempted UID deletes use the same final-disk-state policy, while UID outcomes never drive resource metadata repair.
- PhysicalDeleteResult contains only final reconciled lists: verified deleted resources, verified deleted UID sidecars, verified failures, and genuinely unclear failures. Preliminary or contradictory first observations never enter terminal result lists, and a path cannot be both verified deleted and failed/unclear.
- Repairs metadata only from final verified deleted resource paths: all virtual references to deleted scripts and direct scene entries are removed across every system, while script entries linked to deleted scenes are retained with their scene link cleared. Only files that remain verified present or genuinely unclear retain metadata references.
