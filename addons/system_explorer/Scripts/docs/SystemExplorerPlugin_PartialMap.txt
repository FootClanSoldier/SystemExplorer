Partials/SystemExplorerPlugin.TreeKeyboardNavigation.cs
- Owns the continuous keyboard-navigation chain between the exact System Name LineEdit, exact Filter Items LineEdit, hidden _focusReleaseTarget tree context, and direct Tree.GuiInput, while retaining the shared visible-TreeItem arrow algorithm for both tree routes.
- Keeps global input ownership restricted to the exact two dock LineEdits and exact valid hidden focus-release target, reserves unmodified Escape only for those LineEdits and active filter-result tree contexts, and leaves unfiltered hidden/direct Tree Escape available to the normal shortcut dispatcher.
- Treats unmodified pressed Up, Down, Left, and Right as reserved core navigation commands with higher priority than every rebindable shortcut; one ordinary arrow event crosses at most one control boundary, while each verified boundary transition registers a one-shot continuation for the next matching Echo. That continuation is taken exactly once and can carry a held arrow onward through System Name, Filter Items, and tree context; a successful boundary transition during the continuation registers the next step, matching release or a fresh non-echo press clears stale state, and ordinary TreeItem-to-TreeItem repeat remains unrestricted. Arrow-triggered LineEdit transitions first give the exact target control hidden focus, then explicitly activate editing, and are only registered as successful after both the exact focus owner and IsEditing() have been verified.
- Leaves Ctrl/Shift/Alt/Meta-modified arrows unhandled so TreeShortcutDispatcher.cs can match them as ordinary user bindings; a user binding can never replace the pure arrow navigation commands.
- Navigates visible TreeItems without wrap: Up moves to the previous visible item or, from the first visible row, activates Filter Items and only after verified LineEdit focus/edit activation deselects the current visual Tree selection, refreshes selection-based lock-icon visibility, and clears the nullable persistent selected-item identity through TreeStatePersistence.cs's existing queued save. Control focus alone is never treated as evidence that Tree selection is empty; Down moves to the next visible item; Left collapses an expanded item or moves to the previous visible item; Right expands a collapsed item, enters its first child when already expanded, or moves to the next visible item for leaves. Filter Items Down preserves an already valid visible Tree selection or otherwise selects and scrolls the first visible row before entering the hidden tree context, and stays in the input when no row exists.
- Handles a missing selection defensively by letting Down select the first visible item and Up select the last visible item while Left and Right remain consumed no-ops.
- Selects column 0 and scrolls the item into view without opening scripts/scenes directly or bypassing the existing ItemSelected navigation and persistence flow; active-filter Escape from either tree route delegates to ScriptFilter.cs for exact pre-clear identity capture, normal-tree reveal/rebuild/restore, and deferred return to the hidden tree context without _tree.GrabFocus().

Autocomplete/Semantics/CSharpSemanticMemberCoordinator.cs
- Owns the semantic channel's single controlled Task.Run worker loop, replaceable latest project state and active-document request, project-state/active-state versions, active build cancellation, and limited reportable diagnostics. - Implements latest-request-wins across project generations and active revisions: project changes invalidate/cancel old semantic work and clear the published member snapshot; newer active captures replace pending work and clear the published snapshot immediately so stale members are never served while analysis catches up.
- Preserves a base build already in progress when only the active revision changes and the base is not ready yet; once the worker reports a matching base, superseding active revisions cancel active analysis cooperatively. Publication requires the current project state, active state, revision/path, no newer pending request, and the shared lifetime gate.
- Reset/script-change/shutdown paths invalidate semantic publication and pending state without polling, blocking waits, timers, Godot references, or a separate assembly-unload handler.

Autocomplete/Semantics/CSharpSemanticMemberWorker.cs
- Owns all CSharpCompilation, SemanticModel, SyntaxTree, and Roslyn symbol usage for member completion; these objects remain worker-internal and are never exposed to completion sources or published snapshots.
- Builds a reusable base CSharpCompilation from the already-published CSharpProjectIndexSnapshot file list, reading only those GlobalPath values on the worker and best-effort checking length/UTC mtime fingerprints before and after each read. It does not perform a second project inventory.
- Parses each fingerprint-matching project source with CSharpSyntaxParseProfile.ParseOptions and caches the base compilation plus resource-path-to-tree map by project generation/project-state version. Active revisions with the same project state reuse that base instead of reparsing the whole project.
- For active analysis, parses the captured unsaved SourceText with the same parse profile and immutably replaces the matching disk SyntaxTree in a derived compilation, or adds the tree if the file was absent, leaving the cached base compilation untouched.
- Traverses only SimpleMemberAccessExpression syntax. Normal accesses with a real member identifier on the same line as the operator continue to use Identifier.SpanStart. Incomplete ordinary-dot accesses with a missing member identifier use a real non-missing DotToken's Span.End as both the semantic LookupSymbols position and published member-start coordinate. If Roslyn instead recovers an incomplete dot by binding a real member identifier from any later line, including across blank lines and regardless of that identifier's text, the access is treated as line-local bare-dot parser recovery and likewise uses the original DotToken.Span.End coordinate. Base-expression and semantically identified type-name/static receivers remain rejected; receiver resolution/project-source/member filtering is otherwise unchanged, and the worker does not rewrite source/syntax or create a speculative extra compilation for bare-dot.
- Uses SemanticModel.LookupSymbols(position, container: receiverType, includeReducedExtensionMethods: false) so Roslyn supplies accessibility at the real source position, then keeps only non-static/non-implicit members declared directly on the receiver OriginalDefinition. Supported v1 symbols are non-generic ordinary methods, non-indexer properties, fields, and events; inherited members, constructors/operators/accessors/indexers, generic methods, and extension methods are excluded. Method overloads are collapsed by name/kind with OverloadCount retained as plain data.

Autocomplete/AutocompleteCompletionCoordinator.cs
- Owns request orchestration, the deferred validation generation, the current AutocompleteCompletionSession, and the narrow ordinary native request used to recover a dormant full-member session.
- On replacement CodeCompletionRequested, extracts the current request before invalidating the existing session and treats an already-published full empty-prefix MemberAccess session specially only when the normalized script path, request kind, caret line, and PrefixStartColumn still form the exact same anchor. A same-anchor matching request republishes the complete cached list through AutocompleteCodeEditPresenter and marks the session Active without querying completion sources; a same-anchor no-match request marks the session Dormant, cancels only the native popup once, preserves the cached list/anchor, and does not query sources.
- Deferred TextChanged validation separates native popup cancellation from full session invalidation. Active + same-anchor match performs no request; Active + same-anchor no-match transitions once to Dormant and closes the native popup while preserving the reusable full session; Dormant + continued no-match does nothing; Dormant + a newly available match issues one ordinary RequestCodeCompletion(false), leaving the session Dormant until the normal CodeCompletionRequested callback actually republishes the cached full list through AutocompleteCodeEditPresenter and marks it Active.
- The dormant recovery request is transition-gated so continued matching edits do not request again if Godot ignores the ordinary request; another no-match state re-arms a later Dormant-to-matching transition. No completion request is issued for every TextChanged, and all AddCodeCompletionOption/UpdateCodeCompletionOptions calls remain presenter-owned.
- When the request is not the same exact anchor or the session is not a reusable full empty-prefix MemberAccess session, preserves the conservative replacement behavior: invalidate the old session, query registered completion sources only when a new completion list actually needs to be produced from CodeCompletionRequested, gather valid source items in source/item order, and publish only after all sources complete. Unsupported/extraction failure, anchor leave, lifecycle invalidation, reload reset, shutdown, and ordinary non-reusable session failure still fully invalidate state and cancel native completion where applicable.
- Executes each source call, returned-result enumeration, and item copy behind its own exception boundary; a failed source is discarded, logged through the injected DebugState-aware operation delegate with source type, active script path, and exception detail, and cannot stop later sources or escape the Godot signal callback.
- Uses AutocompleteCompletionMatchPolicy for initial publication and current-prefix availability only; dormant recovery never performs a semantic/source re-query and instead reuses the already-verified complete item list for that exact member-access anchor.

- Stores a defensive copy of the completion items actually published to the native CodeEdit list together with the published request's normalized script path, request kind, caret line, PrefixStartColumn, and published prefix; CaretColumn is intentionally not part of the stable session anchor because it moves as the prefix grows or shrinks.
- Separates exact anchor identity from current match availability: BelongsToSameAnchor compares normalized script path, request kind, caret line, and PrefixStartColumn, while HasAvailableMatch delegates only the current prefix against the shared AutocompleteCompletionMatchPolicy.
- A session published for empty MemberAccess prefix is explicitly the complete list for exactly that access and can be Active or Dormant. Dormant means the native popup is closed because the current same-anchor prefix has no available match, while the complete cached item list and exact anchor remain valid; when a match returns, one transition-gated ordinary recovery request can re-enter the normal callback/presenter publication path, and the session becomes Active only after that cached list is actually republished.
- A same-anchor no-match refreshes the dormant recovery gate without destroying the session, while a different anchor or full lifecycle invalidation still destroys it. Sessions originally published from a non-empty prefix are not complete replacement caches and retain the existing conservative continuation/invalidation behavior rather than receiving general dormant recovery semantics.
